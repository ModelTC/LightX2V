# H3-Image two-step PDMD with DMD2 GAN

This recipe adds DMD2's non-saturating logistic generator/discriminator losses
to the existing official projected-DMD training loop. The discriminator
shares the full trainable fake-score transformer and reads its image-token
features through an FP32 classifier. The token-pooling classifier adapts
DMD2's convolutional SD head to H3; this is not an official H3-Image GAN recipe.

The user-selected GAN positives are **images generated by the released
six-step H3-Image teacher**, not Fine-T2I image files. Preprocessing keeps the
teacher's final latent directly, paired with the same PE text condition.
No VAE encoding or decoding is needed. Each GPU independently generates its
shard, and completed samples are reused after a restart.

## Settings

| Setting | Value |
| --- | --- |
| GPUs | One ACP node, eight H200 GPUs |
| Resolution / prompts | 2048 × 2048 / 10,000 Fine-T2I prompts |
| Student steps / physical sigmas | 2 / `[1, 0.75, 0]` |
| GAN-positive teacher | Released six heads and original six-step sigma grid |
| Update order | Five fake updates, then one student update |
| Student / fake LR | `2e-5` / `4e-6` |
| Student adaptation | LoRA rank/alpha 128/128; AdaLN and `norm_out.linear` 16/16 |
| Fake adaptation | Full transformer plus GAN classifier |
| GAN weights | Generator `0.005`; discriminator `0.01` |
| Training budget | 15,000 role updates = 2,500 student + 12,500 fake |
| Save / retention | Every 100 role updates / retain 2; automatic resume |
| EMA / CFG / DeCFG | No EMA; guidance 1; no DeCFG |

The two-step student and continuous score queries keep the existing
`released_interval_start` head policy. Extending a released six-head model
to continuous scores remains experimental. GAN-positive generation itself
uses the original six-step sampler without that off-grid extension.

## Launch

First prepare the packages and model files described in
[the image environment guide](minimax_h3_image_pdmd2.md#environment-and-weights).
Sync the modified code to the ACP worker, then run once on that worker:

```bash
cd /mnt/lm_data_afs/gushiqiao/codes/news/LightX2V
source /mnt/lm_data_afs/gushiqiao/envs/lightx2v_h3/bin/activate

CUDA_VISIBLE_DEVICES=0,1,2,3,4,5,6,7 \
H3_CODE_ROOT="$PWD" \
H3_PYTHON="$VIRTUAL_ENV/bin/python" \
H3_IMAGE_MODEL_PATH=/mnt/lm_data_afs/gushiqiao/models/MiniMax-H3-Image \
H3_IMAGE_PE_MODEL_PATH=/mnt/lm_data_afs/gushiqiao/models/MiniMax-H3-Image-PE \
H3_IMAGE_DATASET_DIR=/mnt/lm_data_afs/gushiqiao/datasets/minimax_h3_image_finet2i_10k_2048 \
H3_IMAGE_GAN_REAL_DIR=/mnt/lm_data_afs/gushiqiao/datasets/minimax_h3_image_finet2i_10k_2048/gan_real_cache \
H3_IMAGE_PDMD_OUTPUT=/mnt/devsft_afs_2/gushiqiao/outputs/h3_image_pdmd2_gan_teacher6_10k_2048 \
H3_IMAGE_PROMPT_COUNT=10000 \
H3_IMAGE_MAX_ITERS=15000 \
KERNELS_CACHE=/mnt/lm_data_afs/gushiqiao/cache/kernels \
bash lightx2v_train/scripts/run_minimax_h3_image_pdmd2_gan_fsdp8_acp.sh
```

The launcher executes prompt selection → PE → text cache → six-step teacher
latent cache → FSDP training, releasing each stage's models before the next.
It checks both caches before starting training. Add `--dry-run` to inspect
the plan without downloading, loading models, or writing files.

Config:
`configs/train/dmd/minimax_h3_image_pdmd2_gan_2048_r128_a128_fsdp8.yaml`.
Use a new output directory when switching between PDMD, PDMD+GAN and PDD;
their optimizer/checkpoint recipes differ.

All preprocessing output and training stdout/stderr go to
`$H3_IMAGE_PDMD_OUTPUT/logs/launch.*.log`. Checkpoints are written under
`$H3_IMAGE_PDMD_OUTPUT/train/checkpoint-*`.

```bash
tail -F "$(ls -t /mnt/devsft_afs_2/gushiqiao/outputs/h3_image_pdmd2_gan_teacher6_10k_2048/logs/launch.*.log | head -n 1)"
```

The full FP32 fake model and its Adam state require more memory than PDD's
student-only training. The earlier two-GPU PDD memory measurement does not
apply to this recipe; full eight-GPU GAN memory and convergence have not yet
been measured.

## Validation

- The real 33B teacher generated a 2048², six-step positive using a cached
  301-token PE condition. The actual GAN data stream loaded its paired FP32
  latent successfully. Restarting reused the sample without loading a model;
  the eight-rank cache-resume path also passed.
- A small real Image transformer completed two-GPU FSDP training: five fake
  updates → checkpoint → resume into the student GAN update → two further
  fake updates. Student weights, classifier weights, optimizer steps and the
  data cursor were checked across recovery.
- That test exposed a PyTorch 2.8 FSDP precision-cache issue when the first
  resumed fake forward occurs while its parameters are frozen for G. The GAN
  context now refreshes that cache after unfreezing, retaining FP32 master
  weights and FP32 gradient reduction. A separate two-process regression
  covers this boundary.

These are execution/recovery checks, not an eight-GPU convergence experiment.
The full training command above has not been launched locally.
