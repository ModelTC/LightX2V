# 优化探索报告交付检查

`check_exploration_report.py` 对[探索报告](EXPLORATION_REPORT_TEMPLATE.md)执行离线、可重复的交付检查，不需要 GPU 或第三方 Python 包。任务沿用原工作包和报告，检查器不另维护方法/候选状态。

```bash
python tools/check_exploration_report.py --report /task/REPORT.md --output /task/REPORT_CHECKS.json
python tools/check_exploration_report.py --verify /task/REPORT_CHECKS.json --expected-report /task/REPORT.md
```

第一条命令写通过或失败收据；任一错误以退出码1拒绝通过。交付消费者运行第二条，绑定本任务报告路径并重新检查当前文件及身份，不能借另一份报告的通过收据；报告、被读取的Markdown/审核HTML或检查器变动后，旧收据失效。检查收据通过任务工作包引用；不要在报告内链接收据，否则会形成自身哈希依赖。收据不证明内容真实，也不是防伪签名。

当前机械检查范围：

- 七部分编号齐全且顺序正确，忽略 fenced code 和 HTML 注释中的示例。
- 表格数据行标“待审／待质量审核／待画面审核／待媒体审核／pending review”时，就近提供非空本地HTML审核页、图片/视频，或能沿链接到达这些媒体入口的Markdown页面/候选专属锚点。表头、源码待审和明确“无待审”不算媒体待审。Markdown锚点只查对应表格行或到下一标题前的内容，不能借用相邻候选的入口或循环引用自身；允许空行及分段展示原图。格式和入口可达不证明实际查看器能渲染，报告应采用当前使用者可查看的呈现方式。
- 报告本地Markdown链接及Markdown/HTML锚点可达；显式id与标题生成锚点在不同源行同名时拒绝歧义，同一源行的同一目的地可保留；纯外链不做离线通过认证。没有本地入口的外部审核页会明确报错，需先保存可核验的本地审核材料。
- 表格中裸露的“关联待核”拒绝通过；“未接线”必须同时有明确处置。工具只识别这些显式未闭合状态，不推断所有别名，也不能证明所填理由充分。

Markdown输入采用现有模板的单行表格、行内链接、显式参考链接 `[标签][引用]`（单行定义、0–3空格缩进，标签按大小写/空白归一化并使用首个匹配定义）、ATX标题及HTML `id` 或 `<a name>` 锚点；不替代完整Markdown渲染器。不解析嵌入页面的任意JavaScript，不验证视频能否播放、左右选项是否正确，也不从页面存在推断质量批准。未解析的tensor/媒体等payload只检查存在；其内容身份沿用自身运行/质量收据，避免为排版校验重读巨量张量或重跑模型。

检查通过后仍须沿skill执行语义回扫：真实数据流与方法子项是否遗漏、适用前提和暂缓依据是否充分、必要且可执行动作是否留下、报告数字是否匹配实际证据。该审查沿用当前任务记录；不以新字段齐全或脚本通过替代。

**约束的实际边界：** 当前工具只能拒绝签发或复验自己的通过收据，不能阻止Agent绕过它发送消息，也不会修改任务完成状态。需要不可绕过的约束时，必须让实际发布/归档/任务结束消费者调用 `--verify` 并在非零退出时停止；没有接入该消费者就不能宣称已经强制执行。实际任务的证据验收与维护工具的回归测试分别进行；本功能不增加项目CI步骤。

## 何时运行工具回归

由开发/维护Agent按改动影响主动手动运行，不等待开发者逐次提醒，也不将回归测试加入每次模型实验的默认流程：

- 修改工具或测试时，先运行受影响的测试文件；修复具体问题时核对应反例和正常路径，避免只证明拒绝而误拦合法用法。
- 跨模块修改、共享合同变化或影响范围不明确时，交付前集中运行相关组合；影响整体验收链时再执行完整探索回归。
- 仅改文档/注释且执行语义未变，或普通模型实验未改这些工具时，可复用身份与适用范围明确的既有结果；不重复运行无关测试。
- 保存实际源码身份、命令、环境、退出及失败处置。CPU测试只证明对应工具合同；GPU数值/性能、真实宿主接线及skill探索效果按受影响范围另验。

从仓库根目录选择需要的范围执行，例如：

```bash
python -B -m unittest discover -s tests -p "test_exploration_lifecycle.py" -v
```

确需完整回归时使用：

```bash
python -B -m unittest discover -s tests -p "test_exploration_*.py" -v
```

### 按行为审查测试

开发者可先审下表中的行为取舍，再抽查关键实现。维护Agent负责核对夹具、断言与真实接口的关系，检查测试是否会漏错或误拦，按风险补充独立复核，并提供运行证据；通过数量不能代替这些判断。

| 测试入口 | 应当允许的情况 | 应当拒绝或识别的问题 |
|---|---|---|
| [报告](../tests/test_exploration_report.py) | 合法章节/链接及候选自己的审核入口；有据暂缓 | 缺入口、借用其他候选入口、循环锚点及过期收据 |
| [证据](../tests/test_exploration_evidence.py) | 从对齐的原始样本复算统计，保留输入及数值验证范围 | 聚合数值不符、重复/缺失样本、输入/精度/环境不一致 |
| [整体验收](../tests/test_exploration_acceptance.py) | 有据源码裁决、局部负结果与合理暂缓 | 漏必要子项、错对象/粒度、无效资源和用局部交付关闭父任务 |
| [依赖与复核](../tests/test_exploration_lifecycle.py) | 必要补证先执行，未受影响成果继续复用 | 未闭合发现被放行、动作被替换、关联变化未重开或自填批准 |
| [完成适配](../tests/test_exploration_stop_hook.py) | 调用已登记的完成消费者，恢复缺口并允许中断 | 配置缺失、检查器被替换、伪完成及局部范围越权关闭父任务 |

这些临时夹具不是GPU实测结果；适配器的Python/子进程检查也不证明真实宿主已接通。正式接口或能力演进时，核实新需求后同步调整工具及相关测试，不把当前测试样例当成永久模型/平台约束。

## 必要子项、证据与声明验收

结构检查不能证明方法子项已闭合，也不能校核性能数字。完整模型探索正式收口必须使用下述任务级验收，不能因未接线就退成口头自检。验收使用 `tools.exploration_acceptance`，读取器复用 `tools.exploration_evidence`；当前任务的请求格式和完成语义仍由任务接线负责。它不启动模型或GPU监测，不把某个模型的私有summary变成公共前提。

| 使用情形 | 义务与实际保证 |
|---|---|
| 探索途中、专项和阶段交付 | 按问题选择最小充分证据，准确声明范围，按已采用的合同验收；不要求每次候选实验另建整套接线，局部通过不关闭父任务。 |
| 完整模型探索正式收口 | 真实完成入口强制消费当前固定必要项、原件证据、报告及必修发现闭合；缺失、过期或失败不能写完成。未接通时父任务保持未完成，并记录缺失接线。 |
| 复核、依赖变化与动作准入 | 语义复核、依赖变化重评和高成本动作的前置判断均须履行，必要发现须核闭合；可选的是下述 lifecycle 的具体实现。用其他实现替代时核实际 runner/完成消费者的等价保证，Agent 的承诺不替代机械检查，已采用的合同不能自行跳过。 |
| 指定宿主适配 | 按明确宿主合同接入并验证，不默认安装全局 hook；任务 finish 的强制检查与宿主最终消息的控制边界分别说明。 |

### 可运行的最小接线示例

先运行 [源码局部交付示例](examples/exploration_source_task.py)，无需阅读测试夹具、安装依赖或使用GPU。选择尚不存在的任务目录，保留 `init` 打印的绑定SHA256，再原样交给 `verify`：

```bash
python -B tools/examples/exploration_source_task.py init /tmp/exploration-source-task
python -B tools/examples/exploration_source_task.py verify /tmp/exploration-source-task --binding-sha256 PRINTED_SHA256
```

`init` 显式生成示例原件、固定policy、唯一工作包、Markdown报告、绑定和收据；`verify` 在导入前核执行依赖，再从原件重建事实并复验当前报告和旧收据，不重写文件。两者都应返回 `passed=true, task_complete=false`。修改原件、policy、报告、执行依赖或把父任务伪改为完成后，复验应拒绝；重新运行 `init` 也不能覆盖旧目录。

本例只有源码身份事实和局部交付消费者，其精简MAP及暂缓理由用于演示接口，不证明方法发现充分或完整模型优化完成。真实任务复用已有工作包和生产记录，替换示例的初始化、collector及完成范围；性能事实仍须核实际运行，不能照抄测试里的无条件 `valid=True`。源码/输入条件未变时复用有效结果，示例不是每次实验新增一套目录或验收工程的要求。

### 随任务和项目演进调整

固定绑定用于识别一次验收依据的版本。换模型、平台或LightX2V实现时，应根据实际目标、生产者/消费者与可用证据重新确定必要子项、依赖、验证粒度和任务接线，不继承旧任务的清单、路径、backend或格式假设作为永久限制。

旧policy、读取器或报告合同无法表达新情况时，在已有授权内明确受影响范围，修订任务适配；需要改变通用接口时连同相应验证一起更新，再登记新绑定与收据。保留旧快照和有效原始事实，未受影响部分继续复用；排版或接口迁移不自动要求重跑模型。检查失败应帮助定位变化和补证，不能据此把新模型判成不支持，或删去必要探索项来迁就旧检查。刷新散列只说明接受了新版本，不能代替对新语义的核实。

### 谁持有预期，谁维护活动状态

沿用任务唯一活动工作包，把当前子项的处置、理由、证据引用及重开条件放入 `exploration_fulfillment`。验收使用消费者持有的固定policy及SHA256，不能从活动记录倒推“本来应该检查哪些项”。policy是已确认范围和发现基准的版本快照，包含：

- `task_id`、`scope_id`、`scope_label`、实际报告路径及当前方法库路径/散列。
- `items`：稳定标识、方法族、实际位置、要回答的问题、父子关系和允许的证据引用。族标识从当前地图的三级标题派生，不固定族数；标题兼具展示与接口作用，改名须核范围及绑定影响，不能当作纯排版无条件沿用旧身份；每族至少有一个有据处置，必要子项由双向发现及语义复核确认。
- `evidence`：预期类型与从原生产物核对的对象、输入、配置、平台和验证范围；路径及任务接线参数可随对应生产者保存。`artifacts`固定原始来源的路径/散列。
- `claims`、`report_blocks`、`report_context`：报告实际消费哪些事实、表格列名及关键段落的上下文身份。`required_action_ids`固定收口前不能静默删去的必要行动；`artifacts`也是复核与依赖文件的唯一预期内容身份，不另复制review/dependency散列。

已登记范围不能由删活动项或改一个开关缩小。发现新子项、方法库或任务条件变化时，保留旧快照和增删/合并理由，明确受影响项，修订范围版本及消费者绑定，再验收。正常范围修订按任务已有授权执行；这不是逐项请求开发者批准的流程。同权限作者仍能修改这些文件，权限外隔离由实际宿主负责。

### 原始读取与证据强度

任务接线先固定并读取检查器/读取器及其执行依赖，随后 `load_policy`建立读取边界，再用 `Inputs`读取实际文件，将原始来源、数值、对象身份和限制交给 `check`。此边界之后消费的全部原始及辅助来源必须在固定`artifacts`中，不能只登记最终显示的主引用。读取器必须在进入业务代码之前由消费者固定身份；不接受把作者手填对象映射重新命名为原始证据。当前公共读取器支持：

| 入口 | 实际核对 | 保留的限制 |
|---|---|---|
| `source_reference` | 文件当前内容和身份 | 定位及关联需语义复核，不证明实测性能 |
| `module_comparison` | `(report, raw)`对；原`module_benchmark_v1`、逐rank raw及完整measurement group、样本对齐、max-rank聚合、任务记录的factory | 完整保留factory配置，不支持无正式consumer的candidate别名。原preflight不等于重算payload误差，工厂上下文不独立证明dispatch；运行有效性默认未验证 |
| `operator_comparison` | 原算子raw的canonical对象及完整执行输入身份（family/shape/routing/replay/sparse/dtype）、后端precision/environment、成对run_id/seed/计时设置、正常mean再聚合 | 来源注释可更新并保留全部版本；按实际replay或合成分类。未做correctness仍未验，不外推block/请求收益；运行有效性默认未验证 |

公共原生读取器只核样本格式与统计，不要求某套GPU监督目录，也不替任务验证执行。其测量事实默认 `valid=False`；固定任务collector按实际平台核对每个父/候选运行的命令、输入/配置、正常样本与输出名单及内容身份、退出、资源和收尾，再将实际读取的监督原件加入 `sources`，全部登记到 `artifacts` 后才明确置 `valid=True`。核心只接受布尔True，不能用手填通过摘要代替原件核验。CPU与不同设备的监督由其真实工具/任务owner处理，不伪造GPU采样来适配读取器。

恢复或append须逐来源关联实际运行；新成功作业不能认可旧无效样本。原格式没有可核归属时，保留历史数字及限制，不能靠后来新建登记表、目录接近或时间相近补成执行证明。从旧版迁移时，监督格式解析留任务adapter，原生读数与运行有效性分别验证；没有新增通用runner、回调注册或监督schema。

完整请求读取器放在任务脚本：沿实际生产命令/配置核原始逐rank记录，分开真实预热、诊断和正常样本；同一比较不拼跨组父方案或累计。媒体须绑定真实父子正常输出、页面实际选项与媒体身份，而不只是路径存在。无法补齐的旧格式缺口写入限制；需要更强结论时才补对应观测，不生成貌似成功的新收据覆盖旧缺口。

同一检查中的原始读取可复用缓存；收据绑定全部实际读取输入、工具与报告。大型payload的复核频度按其身份保护与结论风险决定；沿用原生数值摘要时明确未重新逐值计算的层级。源码不适用、有据暂缓或局部负结果不强制补完整请求；性能保留/拒绝不能仅由源码引用支撑。研究候选媒体待审可以闭合声明范围，但不授予感知质量或生产批准。

### 让人读声明消费同一事实

以 `rendered_blocks`生成主结果、摘要、组合、质量/资源表中的必要片段，再由 `check`从同源事实重建并逐字核对；它不推断任意自然语言。表格由完整保护块包围，避免在每行之间插注释破坏Markdown表格：

```markdown
<!-- exploration:results -->

| 项目 | 范围 | 时间 | 处置 |
|---|---|---|---|
...由已验事实生成的行...

<!-- /exploration:results -->
```

正式第3节实测结果表使用五列，measurement claim 显式选择 `layout="results"`，并给非空的真实 `parent_label` 和 `change`；`change` 写唯一变化，多因素同改写联合变化。`candidate_label` 可选，默认沿用该项 label。例如在已登记的 claim 和 report_blocks 中设置：

```python
claim.update(layout="results", parent_label="实际父方案", candidate_label="实际候选", change="本次唯一变化及必要依赖")
report_blocks["results"] = (
    "| 优化项及改动方式 | 实际父方案 → 唯一变化 | 验证范围/强度 | 对照 → 方案耗时及延迟降低 | 处置/候选 |\n"
    "|---|---|---|---|---|"
)
```

未指定 layout 的旧 measurement 保留四列紧凑布局，必须配四列表头，不倒改历史报告。源码依据、metric、quality 和 combination 使用各自表形；不能把不同列形混入同一表头。`rendered_blocks` 校核已登记表头/分隔行与生成行的列宽，错误搭配拒绝生成；它不验证任意 Markdown 渲染或这些文字的语义真实性。

方法库折叠视图的`coverage`块由同一子项记录生成。关键第1/3/4/6部分的其余上下文用 `report_context(text, {"coverage", *policy["report_blocks"]})`登记身份，仅排除已登记且由验收逐字核对的块；未知marker内的文字仍受上下文身份约束；已登记的表格块都须消费实际claims，不能声明空块来豁免核对。标题层级与正式模板及结构检查一致。这能防止在正确表格旁另加未绑定结果，但这些文字的初始正确性仍须审核。第2/5/7部分的pipeline解释、取舍分析和交付说明继续按证据语义审查。报告排版/上下文确需修改时，审核后更新相应上下文及消费者policy绑定，再生成新验收；不能用重签结构收据替错误数字或范围担保。

任务接线的核心顺序如下；可运行入口见上方示例，边界行为回归见 [整体验收测试](../tests/test_exploration_acceptance.py)。消费者绑定来自文件时，下面的路径和SHA取其已核定值；绑定为代码常量时路径为None。

```python
inputs = Inputs()
if consumer_binding_path is not None:
    inputs.pinned(consumer_binding_path, consumer_binding_sha256)
for path, sha256 in consumer_checked_code.items():
    inputs.pinned(path, sha256)  # 核全体执行依赖，再导入/调用任务读取器
policy, families = load_policy(inputs, policy_path, consumer_policy_sha256)
facts = collect_native_evidence(inputs, policy)  # 任务负责；固定接线代码身份
result = check(policy, families, work_package, facts, inputs)
completion_state(work_package, result)
write_receipt(result, receipt_path, inputs)
```

`check`失败返回具体子项/声明与原因；输入格式或原生有效性不成立时读取器抛错，任务入口应非零退出。检查/复验本身不改工作包、报告或原始证据。`write_receipt`拒绝与已读/已登记原件或报告碰撞；文件绑定通过`Inputs.pinned`登记后也受此保护。任务CLI另保护可变工作包、发布目标与正在复验的旧收据，拒绝路径及同文件别名碰撞。生成报告是显式写入步骤，不能藏在verify中。

### 在真实完成消费者强制复验

只在skill写“交付前运行”仍可被遗漏。迁入保障的发布器/结束入口应固定任务权威、范围版本、预期报告、必需检查器/任务读取器及收据，且在任何发布写入之前：

1. 从消费者固定位置读取必需绑定；缺配置/工具/收据就拒绝，不能用工作包可选开关退回旧分支。核检查入口和全部执行依赖身份，再运行任务验收。
2. 用相同原始读取器重验，并调用 `verify_receipt`核当前输入和检查器身份；旧passed、外来任务、错范围和改报告都不能继承通过。失败保留原文件和已发布内容，继续修复授权内缺口。
3. 列出消费者所有完成状态，统一走相同检查；未知状态需明确映射。`completed`、`passed`、`passed_with_scope`在本API中都是完成；阻塞、暂停、预算耗尽和局部交付都不是全部完成。
4. 明确父任务是否与受验范围相同。`mode="delivery"`加显式item集合可验局部成果，不产生`task_complete`；父任务仍有必要动作时不能结案。声明范围通过也不能关闭范围更大的项目。研究/源码审核/画面批准/生产采用仍分别记录。

检查器不提供任意Python插件注册或全局任务状态机。任务接线负责自己的生产者与消费者合同，通用部分只精确核已声明范围、证据关联及保护声明。直接修改任务JSON、同权限修改绑定/消费者代码、其他未接入的发布器和宿主最终消息不在这层强制边界内；未接入时明确说明，不能称整个工作流不可绕过。

## 语义复核、动作准入与依赖变化

`exploration_lifecycle.py` 是完成检查的可选强化合同；需要这层保障的消费者必须固定包含 `lifecycle` 的 policy，不能依赖活动文档开关。review 固定内容摘要、任务/范围、发现清单摘要（含证据规格、候选父关系及从artifacts派生的依赖身份）、当前逐项处置摘要、实际执行记录、实际输入和四类判断。`lifecycle.review`仅引用path，review与execution原件在读取当场按artifacts核身份，动作与完成入口共用原件登记/版本检查。`review.observed_inputs`保留审核者当时实际看过的版本，不与消费者当前预期混同。

`findings`只放阻塞发现，其ID集合须与固定`lifecycle.required_finding_ids`精确相同；普通建议留说明/notes，不再维护逐行required开关。新必修发现先修订登记范围再准入，不能靠漏列ID或required=False缩小义务。completion按本次items交集核闭合，action允许已明确准入的open整改动作先补证。真实独立性与判断充分性仍由执行/复核证据支持，不由 reviewer 字符串证明。

实际 runner 在启动前调用 `authorize_action`，比对任务/范围、精确命令、cwd、环境、输入和成本；每个声明的动作输入都须在对应动作审核依据及 `observed_inputs` 中登记内容身份，cwd须为实际绝对路径，相对输入按该cwd解析；environment须为显式字符串映射，可空，表示未声明受控环境项。runner在实际执行边界落实cwd和声明的环境项，其余继承环境未由本检查固定。准入默认核全任务新鲜度；需局部复用时，在固定review的该动作决定中登记非空items，并用现有input_items说明输入归属。活动工作包不能自行缩小范围。局部输入须有固定dependency登记，归属覆盖其子项及候选后代影响；只有input_items标签或未标归属/共享输入、catalog/report/checker、动作实际inputs及其复核依据仍核当前身份，不能因标为其他子项而跳过。policy范围或inventory变化仍需更新复核绑定，不自动迁移旧review。它不代替已有 GPU/资源监督。`assess_changes`从artifacts取依赖预期身份，依赖行只保留path/kind/items/candidates，给出子项/候选闭包与失效域；`apply_changes`显式更新唯一工作包，首次重开保留历史决定，重复应用同一变化不再嵌套相同needs_review。历史测量保留，受影响批准撤回；影响清单由调用方保存原件或引用，函数不再把整份assessment复制进活动工作包。候选状态只存candidate_approvals，不再写无人消费的item.approval_state。研究验收支持 `research`、`pending_review`、`rejected`、`needs_review`，拒绝 `approved`；当前没有原生正向批准读取器，已注册普通文件及自填输出/依赖字段不能充当批准。画面或生产采用批准须由对应真实消费者另行处理。

### 局部动作复用的登记片段

下面仅展示固定review的可选局部字段，其余动作签名、复核输入和依赖登记沿用前文；不能在活动工作包里自行填写来降低检查范围：

```python
review["actions"][action_id]["items"] = ["self-attention"]
review["input_items"][attention_source] = ["self-attention", "cross-attention"]
```

归属包含固定依赖及其候选后代影响的全部子项。全局输入可不填映射或映射到全部子项，两者都持续全局核验；不能只列一个无关子项。局部性未登记、不明确或包含在动作实际输入/审核依据中时仍核当前身份。这样可复用未受影响的动作决定，不把另一个分支、全任务完成或新inventory顺带认可。

## 宿主完成适配

`exploration_stop_hook.py --binding PATH --binding-sha256 SHA256` 提供 stdlib 宿主适配，输入原生 hook JSON。先核固定 binding、entry、checker 和 policy 身份，再通过真实消费者复验收据；完成状态的 Stop 失败返回具体缺口并阻止认可的结束，SessionStart 返回恢复上下文，Interrupt 放行中断。`blocked`、`paused`、`budget_exhausted` 可按 `stop_reason` 中记录的真实阻塞或用户限制非完成地停止；`blocked` 的剩余动作还须逐项为有理由的 `blocked`，不能留可执行动作。此路径只核固定接线与任务身份，不调用完成验收、不签发通过或修改任务状态；SessionStart 明示仍未完成，后续恢复由当前事实和用户指令决定。该文字说明及状态本身不证明阻塞属实，语义复核仍须核依据。暂停和预算由宿主原生控制，接入前须实际验证其优先级，不能让失败续接覆盖用户限制。

接线由任务运行器提供，项目不默认安装用户 hook。非 managed hook 的信任、可编辑配置和同 UID 文件不是外部权限隔离；当前 IDE 未接线时，只能声明已验证的任务级入口。外部控制者可持有只读绑定与检查器，正常发布器消费其验收；直接发宿主消息或绕过该入口的权限边界须如实列明。记录 Stop、重启恢复、中断、暂停、预算与篡改路径的实际测试，连续同因失败先诊断或有据阻塞，不无限自动重试。

宿主验收须同时核有效协议输出与原生执行结果，不能仅凭脚本非零退出推断宿主拒绝完成；崩溃、超时或无效协议的处置按实际宿主验证。宿主超时预算须覆盖消费者内部有界校验及适配返回的余量，快速夹具通过不证明慢消费者或超时路径安全。
