# Profiler 的 Agent 用法

工具负责确定性采集/计算/校验，Agent负责选范围、补证和解释，开发者决定优化目标与产品质量。API、schema和指标只查README，不复制另一份长规则。

1. 先确认真实模型/输入/精度/可执行backend和资源权限。核实际加载文件身份；标准合成层不能冒充目标模型。已有证据可复用时核源码/输入/机制身份，不重跑整套测试。
2. 先看完整请求成本，再为当前疑问选择最小同步函数/模块。CLI 导入目标模块会执行其顶层代码，先核可安全导入；不安全时用独立 driver/API，不把额外执行当预热。入口提供同进程真实预热和采集调用，调用不够先修接线；不要暗中重放有状态请求或另启进程预热。
3. 默认关闭record_shapes和计算量统计采干净时间线。需要shape/FLOPs/实际route时再联合统计；检查唯一标记、采样覆盖和实际owner，不以时间临近、相同shape或另一进程的样本补造逐次绑定。
4. 高空隙先核同进程预热和采集/统计开销，再定位CPU准备、同步调用及GPU活动。同步等待与空隙重合只是线索，须追源码依赖才能提冗余同步候选。不同设备、嵌套region和异步尾部不混加。
5. 先核计算量定义与实际计算范围；同一 owner 内也是 GEMM 的路由合并不一定属于专家主体，不按名字或顺序猜配，缺少实际范围保留未知。计算量缺口读 owning core/backend；固定shape/config可唯一决定时用共同数学，数据相关选区读实际最终mask/ranges。MoE同构总量看shape与expert配置，分布/回放才读实际tensor；不按模型扩张统计清单。编译/graph内部不可见保持缺口。
6. 精度未知查实际native API/源码合同，必要时用新进程库日志；设置许可不等于物理执行。新硬件/缺peak时主动查厂商实际SKU/SM及各计算/累加精度，建立有来源的显式文件；代码只消费。未知先报告绝对时间。
7. 主体计算表先读取[共同呈现约定](CORE_COMPUTE_TABLE.md)，按固定列填事实并做交付前格式核对。人读报告先说范围、输入来源、硬件和主要成本；一处可用TB入口。详细事件/证据留facts/折叠参考，不能把审计工作推给开发者。算子bench、模型profile、层级TP/SP比较分开。报告呈现本次性能事实、归因和必要限制；工具问题的发现/修复过程、联合开发历史和提交状态写入任务记录，不进入性能报告正文。
8. 本地保存命令、源码/输入身份、PID/启动身份、日志、产物和退出状态；恢复先核实再重试。只用获准空闲资源，动态监测竞争并丢弃受干扰计时。源码稳定后按风险集中验证，不因小改名反复跑GPU。

性能/资源/数值分别核查，诊断局部改善不替代完整请求A/B。机器路径、权重、trace、一次性记录留本地；稳定事实进代码，指标/边界进README，诊断方法留本指南。不自动改生产默认、批准非零质量差异、提交或推送。

采集命令复用 [gpu_watch](../runtime/README.md) 记录/核对资源；Agent落实实际环境内期限和收尾，仅命令成功、资源check通过且本人任务已收尾时采纳trace，失效trace保留排查。


SP 配置从 benchmark 报告恢复时，核 `diagnostic_configuration_from_report` 的实际候选与 seed，再以 `_prepare_operation` 返回的 `(fn, dense_equivalent_flops)` 调用 Capture；不要依赖旧的第三返回值。沿用本次 repeat 的实际 seed、原输入、全部 head 流水参数和真实组，逐 rank 保存目录；bulk、head 流水及非整除尾组分别查必要证据。正常性能仍看无 profiler 的 benchmark，不把组件模拟诊断冒充真实流水。发生 rank 内部通信异常时依靠有期限的 launcher 收尾，不能在已有 collective 挂起后承诺 Python 层恢复。

## 层输入的捕获与重放

沿真实层调用保存实际输入、所需状态、权重/量化表示及来源；生产调用会复用或原地修改 buffer 时，在安全时点保留值。计算量、shape 或路由摘要不能代替重放 tensor。已有 sparse/MoE 导出回调可复用，整层保存/加载脚本由当前任务组织。

重建生产层与实际并行组，固定捕获位置和配置，恢复每次调用会改变的输入、cache 与随机状态；先比较原层与重放输出，再采性能。有状态层不能无条件重复同一调用。

reset、加载/搬运若在目标调用外，分析时按 `calls.jsonl` 中 active 调用的实际 `scope` 使用 `--scope`，避免把 profiler 窗口内的准备工作计入层成本。
