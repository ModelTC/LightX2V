# 模块性能报告共同结构

单卡和多卡均保留以下分析，多卡增加通信，不替代或省略计算分析。报告只消费本次事实和必要源码归因，不记工具开发过程。

1. 范围、输入来源、硬件/名义峰值、精度及实际配置；若有正常bench，先简述独立测得的层延迟/显存/数值状态。
2. 干净采样总体：GPU跨度、活动并集、主体计算、辅助计算、拷贝、填充、可见空隙。多卡按rank列出，顺序为主体计算、辅助计算、拷贝、填充、通信、计算/通信重叠、可见空隙；活动和空隙同时列毫秒及占本rank GPU跨度比例，重叠只列毫秒。不跨rank相加。
3. 主体计算：按[共同表格约定](CORE_COMPUTE_TABLE.md)展示shape、计算量、GPU覆盖、效率、名义峰值比例和精度；联合采样与正常计时分开。
4. 辅助计算与数据搬运：按名称、次数和GPU覆盖排序。多卡使用capture的auxiliary_activities，已排除通信；完整kernel相同且次数相同时可列rank与时间范围，不将通信重复计入。高耗时项优先，拷贝/填充及当前关注项可单列。
5. 空隙与同步分析：使用干净采样的gap_diagnostics，列各rank主要同步调用、CPU等待、与GPU空隙交集及上层入口；长等待本身不证明冗余同步。联合采样扰动另行说明。
6. 多卡再增加[通信分析](PARALLEL_REPORT_TEMPLATE.md)：先解释实际TP/SP组、调用数与用途，再列逐次collective；明确展示哪个rank，不能将组成员误解为所有两卡连接。按实际host调用顺序，一行一次调用；仅按kernel名不得猜业务阶段。
7. 当前结论、观测范围和必要限制，保留实测源码/输入身份；一个可访问TensorBoard入口，完整逐rank事实留facts。未知事实明确保留，不将工具能力或某组结果外推。
