# 主体计算表呈现约定

单卡模块报告、层级并行报告共用此表；正文解释可以因任务变化，以下字段和格式不由报告生成者自行裁剪。

| 主体 / kernel | 输入 shape | 计算量 GFLOPs | GPU覆盖 ms | 计算效率 TFLOPS | 名义峰值比例 | 计算 / 累加精度 |
|---|---|---:|---:|---:|---:|---|
| {入口或权重简名 · 主体kernel短名} | {实际shape} | {logical_flops/1e9} | {gpu_ms} | {compute_tflops} | {peak_fraction} | {input_dtype / accum_dtype} |

- 单卡不加rank列；多卡只在最左追加`rank`列，其余七列名称、顺序和含义保持一致。不得因多卡省略kernel、峰值比例或精度。kernel调用原有short_name规则；多种主体kernel显示耗时最多者并注明“等N种”。入口、backend和operator名称沿实际身份，不改成臆造的别名。
- 计算量按每次实际本地调用，GFLOPs和毫秒保留3位，TFLOPS保留2位，峰值比例保留1位百分数；采用千位分隔。按GPU覆盖毫秒降序排列；合并行用范围上界排序。
- 数值缺失写“—”，精度未核实写“未知”。缺峰值比例也保留整列。计时不是纯主体时，沿time_basis注明“含辅助”“专家阶段含辅助”或“含LoRA”；LoRA效率缺失不得补算。
- 稀疏计算效率和峰值比例均写为“实际 / 稠密等价*”；仅两种计算量确实不同时追加第二项。星号统一解释为稠密等价量，不是物理利用率，未知项仍留“—*”。
- 每rank同类实际调用不唯一时分行，不按顺序猜配。多rank仅在同一入口/权重、backend、主体kernel集合、shape、计算定义/配置（包括稀疏方法、稀疏率及块大小）、计时口径、精度和名义峰值合同相同时合并。实际选区不同可以合并，计算量、耗时、计算效率、峰值比例各自从逐rank原事实取最小—最大范围；不先平均、相加或用范围端点重算效率。仅一项或舍入后上下界相同时显示单值；shape、算法配置或计时口径不同仍分行。
- GEMM shape写`M/N/K=m/n/k`。Q/K/V shape完全相同时写`Q/K/V=...`，不同时分别列出；其他算子沿实际结构保留shape含义。

报告交付前核对：单卡七列表头、多卡去除rank后的七列表头完全相同，单位/小数位/星号/缺失值遵循以上规则，未丢失已采集字段。只能做格式和分组，数值取工具事实；正常bench计时、干净时间分布和联合计算量保持各自来源。
