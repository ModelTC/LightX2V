# 性能工具导航

进行性能分析、benchmark 或优化前，先核当前项目，再发现可用工具与 skills，最后决定接线与实现方式。

1. **项目现状**：核当前版本、工作区与已有任务状态，按任务相关范围查 README、模型脚本、配置、注册和真实调用链；结合相关依赖变化核已有方法及参考实现。
2. **可用能力**：查本导航、`tools/`、[项目 skills 索引](../.agents/README.md)、实际 `.agents/skills/` 及会话提供的 skills；阅读匹配入口和相关 AGENTS/README，按适用条件与调用约定使用，不将旧名单当当前全集。
3. **复用与补缺**：先组合已有能力并核当前输入/输出、支持边界及证据，再补必要接线或工具。区分工具缺少能力、任务需要接线和已有能力尚未验证，不凭模块可导入认定后端可执行。

| 任务 | 入口 |
|---|---|
| 寻找已有优化方法与参考实现 | [优化方法地图](OPTIMIZATION_MAP.md)，使用前按当前源码补齐或修订 |
| 汇总同一任务的优化探索结果 | [固定报告格式](EXPLORATION_REPORT_TEMPLATE.md) · [交付检查](EXPLORATION_REPORT_CHECKS.md) |
| 真实函数/模块采集、计算量关联与性能分析 | [Profiler 指南](profile/AGENTS.md) · [接口与指标](profile/README.md) |
| Benchmark 与计算量 | [Benchmark 指南](benchmarks/AGENTS.md) · [接口与指标](benchmarks/README.md) |
| GPU 资源观测 | [运行指南](runtime/AGENTS.md) · [工具用法](runtime/README.md) |

在当前工作包简记相关项目入口、实际复用的工具/skills及缺口。没有相关变化的小调整只核增量并复用有效证据，无需每次重读全仓库、另建检查清单或重复测量。

任务特有的输入捕获、重建与状态恢复放在任务脚本；稳定、可复用的精确操作按职责补入工具。源码足以判断或已有证据仍适用时复用；工具回归不为未变能力重复整套测试，优化探索的本轮覆盖按任务目标确定。

交付时区分工具产生的事实、Agent 补写的接线与解释、实际执行的验证范围。任务条件、进程、命令和产物保存到当前工作包；不改变已有资源权限或质量取舍。

## 优化探索

全面发现机会、优先当前瓶颈并按充分粒度验证的模型优化探索使用[explore-model-performance](../.agents/skills/explore-model-performance/SKILL.md)：按方法与成本组织广度/深度、有据组合、预期实测对账、集中质量审核和收口回扫。单独profile/bench保持原任务范围。

方法地图作为共享方法库提供代码方向；[报告模板](EXPLORATION_REPORT_TEMPLATE.md)第二部分先介绍初始化/推理数据流，再呈现从数据流与方法库双向发现的模块/边界×方法子项关系。按模块读的主表与按方法读的索引共用事实，不另建重复状态表。[项目与依赖核验](../.agents/skills/explore-model-performance/references/version-refresh.md)规定使用旧知识前的变化检查。专题流程及维护评估入口只在skill维护，不在本导航复制。

## 工作包与恢复

用一份状态文件统一记录当前任务的进展、证据与待办，已有文件就继续使用。日常进度在当前session说明；有后续复用价值的技术结果按本任务要求写入相应报告，内容与格式由任务性质决定。需要恢复的事实仍同步到状态文件，默认不另建进度文档。字段可合并，已有工具产物用引用，不复制大型清单或另建通用状态引擎。完整模型探索正式收口必须按[交付验收](EXPLORATION_REPORT_CHECKS.md#必要子项证据与声明验收)由实际消费者固定范围快照和读取器身份；其他任务按明确采用的合同执行；它是验收输入，不是第二份活动状态。至少能恢复以下事实：

| 事实 | 需要保留 |
|---|---|
| 目标与授权 | 模型/请求/平台、性能口径、质量/资源/预算、准出条件 |
| 当前身份与入口 | 工作树/版本及依赖、输入与权重身份、相关工具/skills、原始基线和当轮参考 |
| 方法与候选 | 选择/暂缓依据、机制与预期、base/配置差异或patch/依赖、处置/重开条件、组合实际组成 |
| 执行与证据 | 命令、本人进程启动身份/期限、日志/产物/退出及收尾，性能/资源/质量与无效尝试的引用 |
| 下一动作 | 当前步骤、已完成证据、待核实项、下一步和真实阻塞，开发者决定及尚缺授权 |

恢复先核最新指令、实际工作区/版本、本人在途进程和已有产物，再决定续接或重试；版本/输入/执行合同有影响的变化新开对照，确认不受影响才复用旧证据。只补缺失验证，不重复有效运行或建立竞争状态源；具体进程归属/收尾遵循资源指南，Agent 接线与人工归因不包装成工具自动能力。
