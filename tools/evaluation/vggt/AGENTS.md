# 评测项目工程约束

先读README了解运行，DATA了解输入/协议，configs/README了解参数归属；新平台实施与结果交付严格按PLATFORMS.md检查。

- 本项目服务于开发者整模型质量与性能评测；普通用户推理仍使用模型仓库CLI/API。
- 用户明确禁止history/及全部子文件进入PR或提交包。artifacts/、cache/、runtime/、sources/、data/、WORK_LOG.md也只保留本地。检查真实PR文件清单，不能仅依赖.gitignore排除已跟踪文件。
- 运行必需元数据保存在configs/，代码不得读取history/。参考源码依赖通过固定提交与兼容补丁重建，不把完整仓库快照加入提交。
- 评测执行、计时、指标和报告集中在evaluate.py，日常入口为run_eval.sh；外部模型源码不属于评测实现文件合并范围。
- 新平台需要真实设备API、容器/监控和参考基线适配及目标硬件验证；不能只复制JSON或去掉MLU检查。详细步骤、A100接线点、测试矩阵和结果目录见PLATFORMS.md。
- 源码、权重、输入、配置及计时边界必须固定；旧结果不能冒充新源码/平台的新实测，失败和缺失不能从分母删除。
- 变更运行前准备/路径时，验证只含拟提交文件的目录可完成源码准备和输入检查；不依赖作者工作区、预装runtime或旧缓存。
- 修改配置/指标时先运行相关CPU测试，再按受影响范围补实际设备smoke；已有有效证据可复用，不无故重跑整套性能矩阵。
- 原始大产物在独立存储保留SHA清单；经过清理的正式摘要可按PLATFORMS.md提交results/。README保持简洁，不堆放本地工作历史和平台bring-up清单。
