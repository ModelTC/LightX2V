# 模型性能优化探索

以任务的实际性能问题为目标，从当前成本选择优化机会，在足以回答问题的算子/backend、block、阶段或pipeline/请求粒度验证。完整请求不是默认起点或终点；只有整体收益或全局交互结论才要求相应范围的证据。先按“开始与接续”建立项目全貌并发现可用能力，再用任务pipeline覆盖表与共享[方法库](../../../tools/OPTIMIZATION_MAP.md)交叉发现机会；方法库按当前实现更新，不固定方法数量或后端全集。

**全面发现与处置机会，优先当前瓶颈/热点及可消除成本，用最便宜的充分证据决定深挖、扩大验证、组合或暂缓。** 优先级决定顺序和投入，不替代覆盖调查。方法库不是逐项实现配额；广度侦察与热点深挖按价值交替，父方案变化后回扫并重排。在已确认范围内连续推进，阶段或单个候选完成不替代整轮完成。

**按实际任务主动适配变化。** 模型、平台与LightX2V演进时，重新判断方法、必要子项、接线及验证方式；现有规则、方法库和验收接口也应随实际调用修订。绑定约束的是某次验收所依据的范围与事实身份，不冻结探索方案。发现旧合同不适配时，在已有授权内说明影响、调整合同或读取器、补必要验证并更新绑定；复用未受影响证据，不能为通过旧检查强套旧模型假设。具体做法见[变化核验](references/version-refresh.md)。

围绕任务绑定、pipeline/方法展开、按成本筛查与深挖、组合回扫、交付循环推进，质量与过程成本贯穿；阶段可交替，具体批次、实验顺序、重复数和预算留在任务工作包，不固定成所有模型的步骤配额。

## 开始与接续

- 新任务、恢复、继续旧任务或复用历史判断时，执行[项目与依赖变化核验](references/version-refresh.md)。先核已有活动工作包、源码/输入和本人进程，再续接或重试；保留旧版本/实验身份。接续同一任务且相关条件未变时复用有效证据，不因恢复本身重扫全仓库或重跑矩阵；新探索或明确复测要求按本轮目标确定覆盖。材料读取与复用须服从当前任务的独立性及可见范围约定。
- **先建立项目全貌。** 从当前[项目README](../../../README.md)、主要目录、适用AGENTS及实际入口，梳理主要子系统的职责和衔接，辨别模型/算子、平台/并行、训练/推理/服务与工具/测试等边界；概览启动/配置、构造/加载、调度执行和输入输出的关系，定位本轮模型及相关实现。将简要结构与主调用链记入已有工作包，再深入本轮相关路径；划分以当前源码为准，无须通读全仓库，已有有效概览可复用，接续时只补变化。
- **发现当前可用的 skills 和工具。** 从[项目skills索引](../../README.md)与[工具导航](../../../tools/AGENTS.md)进入，对照实际`.agents/skills/`目录（含嵌套入口）和会话提供的能力发现新增或遗漏项。范围包括测量、诊断、实现和平台适配等相关能力，先看名称与适用说明，再按任务需要展开正文；在当前工作包简记相关入口及缺口，不要求逐份加载或执行全部skills。
- 固定模型/权重、代表请求、平台/依赖、精度、计时边界、目标及准出，沿实际启动和请求构建核最终生效值与变换后输入，不能仅凭配置意图固定负载；核验方式见[变化核验](references/version-refresh.md)。沿用已有资源、质量和预算授权，只有无法推断且影响执行/验收的缺项才集中询问。按所选验证范围的成本预估测量/诊断/恢复；Agent估算与开发者硬限制分开。
- 用一份状态文件（如JSON）统一记录本任务的进展、证据和待办，已有文件就继续使用。每个固定任务持续维护一份[七部分总报告](../../../tools/EXPLORATION_REPORT_TEMPLATE.md)，所有有效接续结果回到该入口；冻结批次保留证据身份。条件改变时明确另立对照，不混合不兼容结果。
- 技术结果和影响结论、复现或后续使用的依据写入报告；仅给开发者看的阶段进度、调度/排查经过和接续说明直接在当前session呈现，默认不另建进度文档。影响后续行动的状态仍同步到状态文件，供恢复使用。

## 观测与遍历

1. **先核基线，无须先有候选。** 已有身份/口径有效的基线先复用；缺事实才补对应观测。 沿实际测量入口区分加载、首用、同进程真实输入预热和稳态，重复测量核波动。先用已有证据和低成本调查核任务相关计算、搬运、通信、等待与输出成本；缺哪段且会影响决策才补哪段，不机械全量profile。诊断与正常计时分开，小输入运行不代替代表性负载验证。实际完成边界由任务接线保留。 计时原件在执行时绑定实际worker、输入/配置、输出及监督/退出/收尾；恢复append逐来源核，不用新成功作业替旧样本背书。 记录实际worker的编译/调优缓存设置及来源；工件可含绝对路径，复制目录和改环境变量不证明隔离，复用前核可写目标并保护原件。复用画面批准仍须核实际输出身份。
2. **展开必要子项，逐项给处置。** 先概要还原初始化与每请求推理的数据流、循环/分支和状态边界；从实际模块/搬运/通信/等待找机会，同时从当前方法库反查作用位置及子项，结合源码/配置和相关依赖，汇为一份“作用模块或跨模块边界 × 方法子项”的任务关系。按数据流展示，方法反向索引引用同一关系；激活不等于已启用、已执行或必须实现。未知成本标待观测，不默认为零或低价值。
   对每个适用方向，沿真实producer、调用、consumer及状态owner，展开会改变支持条件、成本、数值或质量要求的必要子项，例如不同阶段/调用、输入形态、可用backend和关键依赖。父项“已检查/已启用”不能代替子项处置；条件等价的重复调用可归并并说明覆盖范围，不穷举无关参数组合。
   对各子项简记原始基线/当前参考的生效状态、可用变体与前提、作用成本、拟验证动作、实际证据及保留/拒绝/暂缓依据和重开条件，计划与结果分开；共享候选/证据只维护一份。会改变工作量或质量的参数，须对账本任务值、生产/库默认值与所测范围；负结果只关闭证据覆盖的条件等价类，不直接扩大为整族结论。已启用仍考虑关闭/调整；未接线、旧guard拒绝和缺资产分别核实，不能直接写成硬件/结构不适用。缺事实先补最小观测，按当前瓶颈、可消除成本、预期收益、资源/质量及实现/验证/审核成本排序，耗时大不等于可优化空间大；不要求实现整张地图。
3. **复用适用的 skills 和工具。** 根据起步时发现的能力，结合当前问题、适用范围、证据需求及接线/验证成本按需选用；出现新问题或能力变化时增量补查。常用入口包括算子后端/配置比较[benchmark-core-ops](../benchmark-core-ops/SKILL.md)、真实模块归因[profile-model-module](../profile-model-module/SKILL.md)、完整模块并行比较[benchmark-module-parallelism](../benchmark-module-parallelism/SKILL.md)；这些导航示例随当前可用能力补充或调整，不要求每次使用全部入口。核真实生产路径与fallback；import或开关存在不证明实际kernel可执行。由本skill组织并显式传入这次调用所需的输入/权重、backend、精度、资源、测量范围及数值参考；独立专业skill依据本次明确输入和自身默认执行，不要求其读取或隐式继承模型请求基线。需要沿用特定生产backend时显式指定，不为上层探索改写下层默认。
4. **实现/测量前记录假设与依据。** 记录候选base/独立差异/依赖、作用机制、当前可影响成本及来源、预期区间或未知、新开销、数值风险和实验顺序/重复预算。优先选可能改变取舍且代价低的动作，同时计入输入接线、加载/编译、测量、质量与审阅成本；外推说明假设，不虚构收益上界或采用概率。允许必要小型接线和实现；未整理代码到约定上限先整理或拒绝，再继续其余范围，不继续堆叠。

首次接线或复核成本偏高时，使用[已有生产者接线与Agent语义复核](references/task-wiring.md)：先复用原生计时/raw和已有任务adapter，再补未覆盖的真实输入、监督与完成边界。技术语义核查由Agent及必要的新上下文复核推进，不默认转交开发者逐项审查。

## 深挖、组合与解释

- 按未决问题选择算子、block、阶段或请求的最小充分验证，可跳过已回答的层级。局部有效可保存独立候选，不必都推进到请求；宣称请求提速才须相应请求证据。局部无益则停止该分支；潜力或关键未知值得投入时再扩大。差异与波动/漂移相当时标“尚未确认收益”，仅在追加证据可能改变取舍且值得其总成本时有界补测，否则暂缓并记重开条件。

- 固定输入及其余条件，同进程必要预热/库autotune后做时间平衡对照；核配置意图与实际执行、漂移和资源竞争。按实际验证范围对账耗时、峰值/结束显存及输出；跨范围解释只复用身份有效的已有证据，不强补未测层级。执行/期限/身份监测、受扰作废与有界重测按[资源指南](../../../tools/runtime/AGENTS.md)，无效原始数据保留。
- 单项指在声明父方案上只改变一个有意义因素；可用原始基线或含必要依赖的真实父方案，记录完整背景。多开关同时改变写联合增量，消融保留其条件含义。有据才选少量组合，核互斥、成本重叠、资源及瓶颈迁移，必要时先测局部交互；按问题价值决定是否扩大到请求。父增量与原始基线总效果分别绑定直接对照，未测标未测，不相加百分比或拼跨批次累计数。
- 预期等价先核严格一致；合理数值差异做分析及同步媒体，性能有效性、技术正确性与画面批准分别记录。遍历中保存证据，报告交付时集中审核，不逐候选等待画面回复。待审方案可作为已授权研究组合父方案，显式保留依赖和组合输出，不能晋升为已接受基线。收到审核决定后绑定实际输出/页面身份；被拒方案及依赖它的组合重新标记，不无条件继承批准，只补受影响验证。NaN、缺帧或实现错误先修复/隔离该分支，继续其他可行工作。
- 在关键取舍、父方案/约束变化后及收口前，主动用真实调用/命令、输入/配置身份、输出和运行收据核对计划、实际行动、记录与结论，保留影响决定的核查依据。发现必要且可执行的缺口，在当前授权内补齐；补表、改措辞或复述规则不等于补证或行动改变。已有事实充分时复用，不为核查额外重跑实验。
- 实测与预期明显不同时，先核实际路径与测量有效性；确认有效后以实测修正判断，保留原预期、结果及差异，原因不明可保留未知。Agent的性能预估是待检验假设，不是实验有效性的判据；用户约定的准出条件另行保留。补测仍按能否改变取舍及总成本决定，工具事实与Agent归因分开。优化或组合改变成本后，回看显露的其他瓶颈与原暂缓方向，再重排下一动作；未受影响的覆盖证据复用。旧模型结论不直接套新环境。

## 收口、回流与停止

交付前回扫 **任务pipeline → 方法及必要子项处置 → 本轮计划/下一动作 → 实际证据 → 总报告 → 配置/patch及依赖**：核真实路径、当前方法库与本次新入口是否有未解释缺口，父项汇总不能掩盖未闭合子项；各项要有实际处置与依据及必要重开条件，未测不写无收益。全面性靠发现与有据处置，不以全部实现/实测计数。约定范围内必要且可执行的空项继续完成；暂缓有成本/合同/范围依据，真实阻塞说明缺什么以及仅影响哪些分支。

范围已回答、剩余价值有证据地不足、开发者预算/资源限制或真实外部阻塞时才收口。Agent批次估算不足先重评计划；一个成功候选、画面待审、未整理候选上限或缺少新通知均不作为整轮提前结束的理由。自主窗口是上限，目标完成也无需额外填满时间。

- 新模型/平台的完整探索收口前，有委派能力时安排一次新上下文独立语义复核：从原题、当前代码和冻结产物核发现与必要子项、负结果范围、重开/停止及最小充分验证，先冻结初审再交换作者解释。必要发现纳入固定范围和实际完成入口，补齐后复验；小接续只核变化，复用未受影响的复核。无法委派时按同一问题自核并说明独立性边界。
- 正式完整收口必须按[交付验收](../../../tools/EXPLORATION_REPORT_CHECKS.md#必要子项证据与声明验收)登记当前必要子项与范围版本，唯一活动记录维护处置，范围变化保留修订依据。固定任务collector核原件对象/配置/输入/粒度与实际运行有效性，让报告结构和关键声明消费同源事实。实际完成入口固定任务/范围/报告及必需检查，发布前复验；缺失、过期或失败拒绝，全部完成别名一致，局部交付不关父任务。高成本动作先由实际runner核精确命令、输入、范围和成本，依赖变化后重评。实际复核覆盖发现、优先级、验证粒度与停止/扩大，绑定当前决定和行动证据；必要发现登记闭合，补证可先执行，避免与最终验收互等。机械通过和元数据不证明发现充分、暂缓充分、判断正确或独立；未接入入口、同权限改写、宿主消息如实标明边界。途中及阶段交付按声明范围继续研究，适用层级与接口细则在验收指南维护。
- 从任务开始在任务记录和运行收据中保存实际过程成本（含纠偏/等待）；报告保留支撑技术或探索效率结论的必要汇总、统计边界和证据入口，日常进度与协作经过在session说明。未采集写未知，不从模型加速反推探索效率。更新唯一总报告：当前完整配置、具体优化项的粒度/真实父方案/验证强度、精选组合的单步/累计、负结果解释、简短质量资源与交付在固定位置，详细证据折叠。旧结果保留原统计/版本，不为排版重算或为填表重测。
- 交付可重跑输入/命令、实际验证范围、独立配置差异或代码patch及依赖。从声明base与依赖实际重建候选，核对覆盖实测改动的源码/配置身份；整理改变语义时只补受影响验证，未闭合标原型或待补证。通用必要代码随功能交付；模型特有输入/状态接线由任务准备并验证，不隐式依赖个人目录。源码审核、画面接受、生产采用及提交授权分别记录，不自动提交/推送/改共享默认。
- 根据实际偏差先区分执行遗漏、工具/接口缺口和规则不适用，在本轮授权内更新受影响知识：成熟机制回工具，方法/支持/反例回现有指南或地图，接口回README；保留触发条件、纠正动作、结果与限制，允许简化或撤回规则，不因单次遗漏叠加通用条款。
- 沉淀经验先提炼机制、成立前提、验证和失败处置，写成通用或条件适用指导；保留有边界的实现例子、反例及工具真实限制。只有本次参数、机器路径、授权与完整实验产物留本地。删除、迁出或抽象化前核可复用知识仍有可发现的正式落点，不能只删专名或省略证明与失效条件；不按模型复制规则或将一次收益升级成全局默认。

需要专门评价工作流作用或改进规则时，参见[行为核查与工作流评估](references/evaluation.md)，按评估问题约定比较方案、独立性、可见材料、预算及证据；普通优化仍按上面的主动核查推进，不默认另开评估实验。
